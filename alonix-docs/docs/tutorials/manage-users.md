# Tutorial: Manage Users

## Overview

Company Admins and Group Admins use this tutorial to practice role changes and safe offboarding—critical for security and compliance.

## Purpose

Build muscle memory for access reviews without learning during an emergency departure.

## Prerequisites

- Admin role (Company or Group Admin per action)
- Test user or colleague willing to participate
- Access to **Users** and **Activity Logs**

## Step-by-Step Instructions

### Step 1: Inventory current users

1. Open **Users**.
2. Export or screenshot list (optional).
3. Note role and workspace per person.

[Screenshot – Users table sorted by role]

### Step 2: Add a test Search User

Follow [Invite Team](/docs/tutorials/invite-team) if you need a test account.

### Step 3: Promote to Group Admin (practice)

1. Edit test user.
2. Change role to **Group Admin** for pilot workspace only.
3. Ask them to confirm new menu items (Connectors, Users).

### Step 4: Demote back to Search User

1. Edit same user.
2. Set role to **Search User**.
3. Confirm admin menus disappear after refresh.

### Step 5: Offboard simulation

For departing users (real or test):

1. Remove workspace access or deactivate account per org policy.
2. Check **Activity Logs**—no new actions after offboard time.
3. Document completion in your access review ticket.

### Step 6: Schedule quarterly review

Calendar recurring task: compare Users list to HR system of record.

## Expected Results

Role changes reflect immediately in UI; offboarded users cannot access data.

## Tips

Never delete accounts without checking legal hold requirements.

## Best Practices

[Workspace Governance](/docs/best-practices/workspace-governance)

## Common Mistakes

Leaving former contractors with Group Admin on unused workspaces.

## Troubleshooting

Cannot edit user—escalate to Company Admin.
