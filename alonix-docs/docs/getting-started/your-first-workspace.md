# Your First Workspace

## Overview

In Alonix, a **workspace** is called a **Group**. Workspaces isolate documents, users, connectors, and settings for a team or project. This guide helps you create a new workspace or get oriented after accepting an invitation.

## Purpose

Establish a dedicated space where your team can upload documents, run the pipeline, and collaborate—with the right people and permissions.

## Prerequisites

- Active Alonix account — see [Creating Your Account](/docs/getting-started/creating-account)
- **Group Admin** or **Company Admin** role to create workspaces (Search Users join via invite only)

## Step-by-Step Instructions

### 1. Create a workspace (admins)

1. Log in to Alonix.
2. Open **Groups** or **Workspaces** in the sidebar.
3. Click **Create workspace** or **New Group**.
4. Enter a clear name (e.g., `Finance – AP 2025`).
5. Add an optional description for your team.
6. Click **Save** or **Create**.

[Screenshot – Create workspace form with name and description fields]

### 2. Join via invitation (all users)

1. Open the invitation email from Alonix.
2. Click **Accept invitation**.
3. Log in or create an account if prompted.
4. You are added to the workspace automatically.

See the [Invite Team tutorial](/docs/tutorials/invite-team) for admin steps.

### 3. Select the workspace

1. Use the **workspace switcher** in the top navigation.
2. Choose your new or assigned workspace.
3. Open the **Dashboard** to confirm you see workspace-specific data.

### 4. Configure basics (Group Admins)

Optional but recommended before inviting others:

- Review default document settings
- Plan folder or tagging conventions — see [Document Organization](/docs/best-practices/document-organization)
- Invite initial team members — [Users](/docs/user-guide/users-and-roles)

### 5. Upload a test document

Follow [Your First Document](/docs/getting-started/your-first-document) to validate the pipeline in this workspace.

## Expected Results

- A new workspace appears in the workspace switcher.
- Invited users can select the workspace after accepting.
- Documents uploaded in this workspace are isolated from other Groups.
- Group Admins can manage users and connectors for this workspace only (unless Company Admin).

## Tips

:::tip Name workspaces for humans
Use names your team recognizes in meetings ("Legal Contracts") rather than cryptic codes ("WS-0042").
:::

- One workspace per team or project reduces permission complexity.
- Company Admins can oversee all workspaces; Group Admins focus on one or a few.

## Best Practices

- Document ownership: assign at least two Group Admins per workspace for continuity.
- Align workspace boundaries with data sensitivity — see [Security and Sensitivity](/docs/best-practices/security-sensitivity).
- Read [Workspace Governance](/docs/best-practices/workspace-governance) before scaling to many Groups.

## Common Mistakes

- Creating duplicate workspaces for the same team.
- Uploading production-sensitive data to a "sandbox" workspace without access controls.
- Inviting users before testing upload and search once.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Cannot create workspace | You need Group Admin or Company Admin role. |
| Workspace not in switcher | Refresh page; confirm invite was accepted. |
| Wrong workspace selected | Re-select in workspace switcher before uploading. |
